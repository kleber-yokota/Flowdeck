Resume guards error | cancelled and branches the SDK path: a failed run is rewound with dbos.RewindWorkflow (cut = the first failed step row · 0-based · WithRewindStartStep · WithRewindQueue(boot.QueueName) · terminal-only · deletes operation_outputs from the cut · recovery_attempts = 0 · same id); a cancelled run is re-enqueued with dbos.ResumeWorkflow (WithResumeQueue(boot.QueueName)) — the SDK SQL re-queues CANCELLED and is a silent no-op on ERROR, which is why the two paths differ. Both ACK enqueued; the detail page offers the Resume button on the error and cancelled pages.core/actions/resume.go · Resume · rewindCut · resumeAck · web/render/templates/execution-detail.html · the Resume button
Cancel is only for live runs (queued/running) — the guard (ErrNotCancellable) is in core/actions; the DBOS cancel flips the row and the ACK reads it back.core/actions/cancel.go · Cancel · ErrNotCancellable · cancelAck
Five UI states: queued · running · success · error · cancelled. reads.MapState: ENQUEUED|DELAYED → queued, PENDING → running, SUCCESS → success, ERROR|MAX_RECOVERY_ATTEMPTS_EXCEEDED → error, CANCELLED → cancelled; terminal = success/error/cancelled (stops the badge poll).core/status/state.go · State · Terminal · core/reads/status.go · MapState · web/executions/badge.go · BadgeFor
Step rows are written on step completion — operation_outputs has no running state, so the executed path shows a step as complete-or-absent; the running state is the workflow badge, not a step state.core/reads/steps.go · stepRows · web/graph/graph.go · groupPath
SDK v1.7.0 · ResumeWorkflow re-enqueues rows with status NOT IN (SUCCESS, ERROR): UPDATE workflow_status SET status = ENQUEUED, queue_name = $2, recovery_attempts = 0, ... WHERE workflow_uuid = ANY($4) AND status NOT IN ($5, $6) — a CANCELLED row is re-enqueued; an ERROR row is a silent no-op (no error returned, row unchanged).dbos/internal/sysdb/system_database.go · SysDB.ResumeWorkflows (the SQL) · dbos/workflow.go · ResumeWorkflow
SDK v1.7.0 · RewindWorkflow is terminal-only (it rejects PENDING/ENQUEUED/DELAYED — cancel it first); it deletes the operation_outputs, workflow_events_history and workflow_output rows with function_id >= startStep, resets recovery_attempts = 0, keeps the same workflow_uuid and re-enqueues (WithRewindQueue); WithRewindStartStep is 0-based.dbos/internal/sysdb/system_database.go · SysDB.RewindWorkflow · dbos/workflow.go · WithRewindStartStep
SDK v1.7.0 · step rows come back ordered ORDER BY function_id ASC — so the index of the first failed row in reads.Steps is the rewind cut (0-based).dbos/internal/sysdb/system_database.go · SysDB.GetWorkflowSteps · core/reads/steps.go · stepRows
