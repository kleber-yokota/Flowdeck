Handoffs — the clean context 3 HANDOFFS

Every agent enters with a clean context: it reads only the files in this table, in their current state — no git history, no previous conversation. The handoff is the whole context.

HandoffFromToReceives (files · current state)

Rules — the hard constraints 7 RULES

  1. Clean context every agent enters clean: the context is only the handoff files — no git tree (files in their current state), no previous conversation.
  2. Ephemeral improve/*.html and tasks/ are deleted after implementation (the last step of the set); bug.md is deleted when the new diagrams are created.
  3. Bug a bug is the task's behavior affecting something the task does not name — caught by the existing tests (a red test).
  4. Stop a red test, a bug, or a step that cannot be done stops the run: report and wait — never skip ahead.
  5. Validate the diagrams are user-validated before they become tasks (agent-diagram ↔ user, until approved).
  6. Two readers every generated diagram: the human SVG + the machine-readable sections, in the same file.
  7. Green state one task = one commit = one green state: the suite passes after every task.

Terms 7 TERMS

TermDefinition
WANT the user's input to the cycle: what to do, in free text.
Cycle one pass of WANT → DONE (or STOP) through the three agents.
Clean context the rule that each agent reads only its handoff files (no git, no history).
Ephemeral deleted after the cycle: improve/*.html, tasks/, bug.md.
Bug the task's behavior affected something it does not name (caught by the existing tests); documented in bug.md.
Red → Green TDD: the failing test first, then the smallest code that makes it pass.
Promotion the last task of the set: promote tasks/fact.md into the folder pages (via index.md); refresh the boundary map only when a frontier or a map row moved.
