# core/reads

The read side of the core: `Executions` (the executions page: the runs of a workflow, newest first, `limit + before` cursor pagination), `Status` (one run: `PENDING` · `ENQUEUED` · `DELAYED` → `queued` · `RUNNING` → `running` · `SUCCESS` → `success` · `ERROR` → `error` · `CANCELLED` → `cancelled`), `Steps` (the step rows of one run, `StepDetail` per step, `wait-row` names `waited` · `wait-frozen`), `Detail` (one run's input · steps · children: `child rows` = the runs dispatched by its steps). Observes durable state only — nothing is executed here.

## Rules (decisions · pinned values)

- The execution rows: `id` · `name` · `state` (the `status.Status` vocabulary: `queued` · `running` · `success` · `error` · `cancelled`) · `created_at` (RFC3339). *(evidence: `executions.go · Execution` · `status.go`)*
- Pagination: `Executions(name, limit, before)` — one SDK `ListWorkflows` call, `WithFilterWorkflowStatuses` over the 6 statuses, `WithFilterSortDesc`, `limit + 1` rows; the last row is dropped and `HasMore` is true (cursor `before` = the last returned id). *(evidence: `executions.go · Executions`)*
- `limit <= 0` → `0` rows, `HasMore` false. *(evidence: `executions.go · Executions`)
- `Status`/`Steps`/`Detail` of an unknown id → `ErrUnknownExecution` (the sentinel shared by the three reads — the web maps it to 404). *(evidence: `status.go · ErrUnknownExecution` · `steps.go` · `detail.go`)*
- `Steps` rows: `step_index` · `name` · `state` (the `status.Status` vocabulary · a `WAIT` step is `waiting` (the run is not yet terminal — `Detail` maps a `WAIT` step of a terminal run to `waited`)) · `input` (a JSON `StepValue`, `null` when the payload is absent) · `output` · `error` (empty until the step errors) · `attempts` (from the SDK's `Attempt` · the attempt counter of the row — `GetStepDetails` is not the place of the retries, it is a read of the attempt of the step that finished last) · `created_at` (RFC3339 · the step's `StartTimestamp`). *(evidence: `steps.go · Step`)*
- The step name is the raw `d.Name` — never a mapping. *(evidence: `steps.go · Step`)*
- A `WAIT` step of a terminal run is `waited` in `Detail`; the `waited` state appears only in `Detail` (a `WAIT` step of a non-terminal run is `waiting` — `Steps` maps it as `running`); the `waiting` state is the live state of a step that is not yet complete (the SDK's `STATUS_WAITING`); the `wait-frozen` row is the frozen step of the `live-frozen` queue (the run is `PENDING`, never executed) — the web reads it with `StepDetail` (the steps of a `PENDING` run have no details yet — `Steps` lists the `wait-frozen` row with the input of the workflow). *(evidence: `detail.go · Detail`)*
- `Detail` children: one row per child run dispatched by the parent's steps (`ChildRun` = `Execution` + `ParentID` + `Step`), listed in dispatch order (the `Step` column names the parent step that dispatched the child). *(evidence: `detail.go · Detail`)*
