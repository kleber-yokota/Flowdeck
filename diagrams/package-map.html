Facts — the verified runtime rows

The verified runtime facts the design depends on (promoted from tasks/fact.md): Fact · Evidence · Validated (author · date · SDK version).

#FactEvidenceValidated
1 dbos.CancelWorkflow(id) cancels a queued/running run: the row becomes CANCELLED and leaves the queue; the workflow stops executing at the start of the next step; an executing step is not interrupted. When no live row is canceled it returns NonExistentWorkflowError. SDK v1.7.0 dbos/workflow.go — CancelWorkflow doc + the len(found) == 0 → models.NewNonExistentWorkflowError path author · 2026-10-31 · dbos v1.7.0
2 A canceled run (SQLite): the row is CANCELLED immediately (a running run: attempts=1; a queued run: attempts=0); the running step finishes in-process but its row is not written (operation_outputs stays empty); the output is not written; the row stays CANCELLED. spike TestSpikeCancelRunning / TestSpikeCancelQueued (temporary core/zz_spike_test.go, deleted) — workflow_status + operation_outputs rows author · 2026-10-31 · dbos v1.7.0

4 SDK-internal step row names: DBOS.sleep · DBOS.select · DBOS.getResult; a loop writes one row per iteration (the same name, spin ×2); an async Go step is a plain row (no async flag). spike TestSpikeKitchenRows — the row dump · the SDK queues_test.go asserts StepName == "DBOS.getResult" author · 2026-10-31 · dbos v1.7.0

7 The steel #8f96a3 is already the CSS token --soft (web/static/style.css); the new --cancelled token carries the same value (per-state naming like --queued/--running/--success/--error). web/static/style.css (the :root tokens) author · 2026-10-31 · code
8 A retries-exhausted run (SQLite): the row's workflow_status.status is ERROR (the distinct MAX_RECOVERY_ATTEMPTS_EXCEEDED status never lands on the row), and dbos.ResumeWorkflow is a no-op on it — nil error, row untouched (the SDK's SQL filter is status NOT IN (SUCCESS, ERROR); CANCELLED rows are re-enqueued).
