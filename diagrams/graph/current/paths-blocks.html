What's inside what — the blocks and the constructs

Every DBOS construct can nest inside any Go block: the block shapes the path (fork / loop / sequence), the construct becomes a node (step / child / async / wait). The left column is the Go syntax a workflow body can use; the right column is what dbos offers to put inside. The same block column makes the rule explicit: no = the item creates a new block, yes = it stays in the current block (no new block). Status = how the parser (core/graph) handles each.
