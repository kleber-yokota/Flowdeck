# web/catalog

The dashboard (the v6.3 console: the live boxes + the wall) and the workflow pages: the workflow list (from the core registry, paginated), and each workflow console (the runline dispatch, the paged executions, the possible-paths block diagram).

## Rules (decisions · pinned values)

- The wall: 20 names per page · `?page` default 1 · clamp [1..pages] · the info `"{start}–{end} de {total}"` (en dash · pt-BR) · prev/next `hx-get` links; an empty registry (or a not-booted core) renders the "No workflows registered" empty state. *(evidence: `dashboard.go · handleWorkflowsList` · `workflowsPage` · `templates/workflows.html`)*
- `GET /live` renders the live partial (the three boxes · the 5s poll · no-store · the fallback 0 · the box hrefs: `/runnings` resolves (the runnings page) · `/queued` resolves (the queued page) · `/failed` resolves (the failed page)). *(evidence: `register.go` · `dashboard.go · handleLive` · `templates/live.html`)*
- The runnings page: `GET /runnings` (the shell · `render.Page` · no data) + `GET /runnings/list` (the partial · `render.Partial` no-store · the 5s poll · the `Port.Living` rows): one row per running run — `wf-name` · `wf-id` (→ `/executions/{id}`) · `ts` (15:04) · the static `running` badge · the elapsed (`<60s` "42s" · `≥60s` "1m 07s") · the empty state `no runs` · `boot.ErrNotLaunched` → 503 via `render.Fail(w, "living", err)`. *(evidence: `runnings.go · handleRunningPage` · `handleRunningList` · `runningRows` · `executions/badge/badge.go · ElapsedLabel` · `templates/runnings.html` · `templates/runnings-list.html`)*
- The queued page: `GET /queued` (the shell · `render.Page` · no data) + `GET /queued/list` (the partial · `render.Partial` no-store · the 5s poll · the `Port.Queued` rows): one row per queued run — `wf-name` · `wf-id` (→ `/executions/{id}`) · `ts` (15:04) · the static `queued` badge · the wait (`<60s` "42s" · `≥60s` "1m 07s") · the empty state `no runs` · `boot.ErrNotLaunched` → 503 via `render.Fail(w, "queued", err)`. *(evidence: `queued.go · handleQueuedPage` · `handleQueuedList` · `queuedRows` · `templates/queued.html` · `templates/queued-list.html`)*
- The failed page: `GET /failed` (the shell · `render.Page` · no data) + `GET /failed/list` (the partial · `render.Partial` no-store · the 5s poll · the `Port.Failed` rows): one row per failed workflow — `wf-name` · `wf-id` (→ `/executions/{id}`) · `ts` (02/01 15:04) · the static `error`/`cancelled` badge · the `message` (the error rows' step error · the cancelled rows empty) · the pager (the wall's shape · `wallPage` 20 · `?page=N`) · the empty state `no failed runs` · `boot.ErrNotLaunched` → 503 via `render.Fail(w, "failed", err)`. *(evidence: `failed.go · handleFailedPage` · `handleFailedList` · `failedRows` · `templates/failed.html` · `templates/failed-list.html`)*
- The workflow page is the console: the cmd line (the back link + `flowdeck workflows {name}` + the breadcrumb from `p.Graph().Files`) and the split (`.split-left`: the runlines · `.graph-side`: the possible-paths graph). *(evidence: `workflow.go · handleWorkflowPage` · `workflowPage` · `templates/workflow.html`)*
- The runline dispatch: the spec form below the dispatch line (`➜` · one input per spec item, the source default prefilled · the `run` button) — `hx-post /run/{name}` · target `#executions` · `hx-swap afterbegin` (the zero payload on no input). *(evidence: `templates/workflow.html` · `executions/dispatch.go · handleRunDispatch`)*
- The runlines: the paged executions — `execPageSize = 6` · `?page=N` (clamped to 1) · `before = (page-1)*execPageSize` via `Port.Executions(name, limit, before)` · no total — the range and older/newer only, one SDK call per page load. *(evidence: `workflow.go · execPager` · `core/reads/executions.go · Executions`)*
- The execrow: the status (the badge) · the elapsed · the step (the last row of `p.Steps(id)`, terminal rows only) · the exit (the decoded output on success, the error message on error) · the cancel button on live states · the resume button on error · the detail link. *(evidence: `workflow.go · handleWorkflowPage` · `templates/exec-row.html`)*
- `execPager(page, count, hasMore)` — the wall's pager shape, no total. *(evidence: `workflow.go · execPager`)*
- The rows use the `web/executions/badge` `Row` view — the badge/row models live in `web/executions/badge`, so catalog does not import `core/status` in production. *(evidence: `workflow.go · workflowPage` · `executions/badge/badge.go · Row`)*
- The graph side: the cmd line + the `BlockToSVG` of `p.Graph().Of(name)` + the legend (`steps are boxes · if forks the branches`) — rendered in this process (map lookup, no re-parse, no DB). *(evidence: `templates/workflow.html` · `web/graph/block · BlockToSVG`)*
- The dispatch form POSTs the raw form values (the dispatch: `web/executions` · the contract: `core/actions`). *(evidence: `workflow.go` · `executions/dispatch.go · handleRunDispatch`)*
